## 1. sushanshetty1/airspace (closest rival, strongest)
**Product.** "Air-traffic control for parallel coding agents." Python `ast` indexer builds a code graph (File, Symbol, CALLS with argument shapes, INHERITS, COVERS from tests). Claude Code hooks (PreToolUse, PostToolUse, Stop, UserPromptSubmit) check every Edit/Write/MultiEdit before it lands and HOLD it if the symbol is claimed by another agent or a new call does not fit a changed signature. Briefings on contract changes, a landing check at Stop, MCP server (6 tools), pre-flight planner, hosted "Tower" web app (radar, pause/message/release), hosted workspaces with GitHub sign-in, live site airspace.sushans.dev, 2:48 demo video.
**FalkorDB use.** Genuinely central. Impact cone `(d)-[:CALLS|COVERS|INHERITS*1..2]->(s)`, atomic lease with fence counter (`CLAIMS {lease_until, fence}`), `shortestPath` for explanations, `algo.WCC` to group parallel work, `algo.betweenness` for hot zones. Also documents FalkorDB quirks (shortestPath must be in WITH/RETURN; MATCH after WITH count() loses rows). Decisions are Cypher + rules, no model call. Fails open if DB is down.
**Claims and measurement.**
- Flask (pinned commit, 83 files, 894 symbols, 491 tests): merged build green 9/9 Airspace, 5/9 broadcast, 0/9 worktrees only. Sample app: 17/18 vs 3/18 vs 0/18. Cost per pair $0.41 vs $0.36 (Flask), 41 s vs 35 s median.
- Evidence: per-run JSON in `server/bench/results/flask` and `final` (diffs, test output, cost, holds, briefed, turns). Reproducible via `uv run python -m airspace.bench.runner --repeat 3` (runner calls `claude` CLI, `--max-turns 25`). Real agent runs, not synthetic. Grading follows the paper "Passes Alone, Fails Together".
- Failures reported: the sample-app miss (Post.__init__, 2/3) is explained; the first Flask run was 7/9 and a real bug found and fixed (flask-v1 kept in repo).
- Verified in a result file (flask-debug-rename--airspace--r1.json): outcome is `"task_failed"` with `a_alone: true, b_alone: false, merged: true`. So the headline "9/9" is the merged-build metric; by the paper's alone-then-merged grading, B's patch fails alone. They disclose this in the README.
**Weaknesses.**
- Task pairs are constructed so that B must call something A renames (task text: "rename get_debug_flag ... Do not keep the old name" vs "use the existing helper"). n=3 per cell, 9 per Flask condition, no p-values or CIs. Their own README concedes the source paper found interference in only 1 of 417 real merged PR pairs. So frequency in the wild is unmeasured.
- Cost and time are higher with Airspace (41 s vs 35 s, $0.41 vs $0.36); no token-parity story beyond the cost column.
- Python only (tree-sitter listed as TODO); misses behaviour changes that keep the signature; roadmap items for Codex/Cursor/Gemini unchecked; demo video/write-up box unchecked in README.
- Memory across sessions is thin (hot zones, notes attached to symbols); no decision capture, no retraction.
**What they have that baton does not.** Real-repo (Flask) benchmark with a three-condition design including a "broadcast" baseline; signature-level call-shape checking (Python argument binding) that blocks the edit, not only warns; landing check at Stop; Tower with pause/message/release controls; hosted deploy plus live site; pre-flight planner with WCC; replay mode; playground needing no agents; academic prior-art citations (two arXiv IDs); 49 server test files; 179 committed bench result files.
**Verdict.** The one to beat. A skeptical judge sees a coherent product, a real-repo A/B with raw runs, and a live site. Weak spot is n=9 and constructed collisions, which is the same weakness baton has but baton has more honest reporting of nulls.

## 2. Quantapixel/hivemind
**Product.** "Shared graph brain for every coding agent on a team." Hooks for Claude Code, Kiro CLI and Codex CLI (payload fixtures for all three in `tests/fixtures/hooks`), plus `hivemind watch` for any tool. Python AST indexer with per-function AST hashes, so it knows exactly which functions changed. Blocks an edit once with the call path (`checkout -> current_user -> validate_token`) and past failed attempts on that code. Failures from test runs become `Attempt` nodes attached to functions, merged on repeats ("seen 3x by alice, bob"), marked resolved with `RESOLVES` when a later run passes. Decisions with SUPERSEDES, conventions, handoffs. Dashboard `hivemind ui` (architecture map, path finder, hotspots by pageRank/betweenness, memory browser, inspector). Vercel-hosted dashboard on FalkorDB Cloud, `hivemind join` onboarding, blog, two demo videos, simulation.
**FalkorDB.** Central: CALLS traversal into other developers' CLAIMS with shortestPath, transitive callers `CALLS*1..3`, `algo.pageRank`, `algo.betweenness`, one graph per team. Uses word-overlap, not embeddings, for consolidation (roadmap lists vector index).
**Claims.** No outcome benchmark found. Evidence is a "Tested with real agents" narrative (Kira/Kiro, Carl/Claude, Cody/Codex on three clones), 63 tests [per README, not re-counted], and captured hook fixtures. Codex automatic capture listed as "not yet verified".
**Weaknesses.** Zero quantified benefit (no with/without runs, no cost). Warning is "blocked once", not enforced. Python only. Free FalkorDB Cloud tier sleeps and deletes after 7 days (their own caveat). Dashboard behind a shared access code.
**Has, baton lacks.** Kiro and Codex support with real payload fixtures; per-function AST-hash change detection; failure-to-fix memory (attempt/resolves chain); hosted dashboard and one-command team join; consolidation of repeats.
**Verdict.** Most feature-complete on capture and integrations; weak on proof. A judge who asks "does it help?" gets a story, not numbers. Baton beats it on evidence; it beats baton on breadth.

## 3. Lecrupus/hivemind
**Product.** Shared time-aware memory + coordination for Claude Code, Cursor, Codex over MCP (22 tools) and 7 Claude Code hooks. Episodes/Facts (bi-temporal, SUPERSEDES with `valid_to`)/Procedures (auto-mined from fail -> fix -> success), known-fix injection on error, file-conflict warning, atomic task claim, handoffs that CARRY facts, private vs team graphs with promote, PageRank + label propagation consolidation, vector + full-text recall (fastembed bge-small), secret redaction, "not in the graph" abstention. Deploy-to-Render button, live demo, 2-min video, "Play the demo" dashboard with time-travel slider.
**FalkorDB.** Very broad use: vector index, full-text, GRAPH.RO_QUERY for reads, multi-graph per workspace and per user, algorithms.
**Claims and measurement.**
- Concurrency: 100 agents, 1,105 ops/s on one graph, 1,301 ops/s on 10 tenant graphs, 0 errors; claim race 20/20 single winner. Run on one 24-core Windows laptop. Reproducible via `bench/concurrency.py`.
- A/B on real Claude Code (Opus 5.5): memory-only scenario 0/2 correct without vs 2/2 with, cost $0.22 -> $0.27 avg (about +23%), turns 4.5 -> 7. In-repo scenario: 2/2 vs 2/2, no difference, stated plainly.
- 18 tests against real FalkorDB. Limitations section is candid (unauthenticated dashboard reads; heuristic mining; Cursor/Codex get MCP only, no hooks).
**Weaknesses.** n=2 per cell, and the "memory-only" scenario is constructed so the rule exists only in memory (no real-world frequency). Costs more with memory. Seeded handoff content, not discovered by agents. The headline correctness result cannot be statistically distinguished from chance at n=2 (0/2 vs 2/2).
**Has, baton lacks.** Vector/semantic recall; Cursor/Codex install commands; Deploy button and live demo; bi-temporal time travel; auto-mined procedures; secret redaction; concurrency benchmark; private/team memory.
**Verdict.** Strong on Track 2 checklist coverage and honest about the null in-repo result. Evidence is thinner than it looks (n=2). Judges reading the rubric (episodic/semantic/procedural, concurrency, per-tenant) will tick every box.

## 4. tharunkumardeveloper/The-Final-Boss (Relay)
**Product.** Not for coding agents: three support-desk agents for a fictional ISP (WiFight) on a shared bi-temporal graph per tenant; Claude can join as a 4th agent via 14 MCP tools. Live site, judge-mode autoplay, staff console, dev.to blog.
**FalkorDB.** Central and well-argued: two clocks (valid_from/valid_to and recorded_at/expired_at), SUPERSEDES, retire, conflict ranking, answer paths, `algo.maxFlow` blast radius, graph-per-tenant, "Remove FalkorDB and..." table.
**Claims.** 160 questions, 40 customers, 556 turns; 99.4% (159/160) vs 61.3% (98/160) vector store; +38.1 points, paired bootstrap 95% CI [+30.6, +45.6], exact McNemar p = 1.4e-17; ablations (-19 pts without two clocks). Reproduce the report with no keys: `python -m eval.run_eval --report` regenerates `results.md` from committed `eval/results.json` (all answers and grades). Full rerun needs FalkorDB + Groq keys.
**Honesty.** Admits data is synthetic from their own templates; reports a loss on LoCoMo (token F1 0.08 vs 0.27); admits benchmark not rerun after a fix.
**Weaknesses.** Domain mismatch (customer support), synthetic questions written by the system author, answer model qwen (not Claude); LoCoMo loss. The vector-store baseline is plain top-10 dated chunks, a fairly weak baseline [my judgment].
**Has, baton lacks.** Statistical rigor (CI, McNemar), ablations, committed raw results, a polished live judge-mode, blog post, 6-region multi-tenant demo.
**Verdict.** Probably the Track 2 front-runner on "evidence and polish" if judges do not require coding agents. Its statistics bar is the one baton must be seen as meeting honestly. Baton's advantage is it solves a real, daily developer problem with real agent runs, where Relay's questions are synthetic.

## 5. tinniaru3005/custody
**Product.** Provenance-tracked shared memory with a deterministic Guard (ALLOW / REQUIRE_APPROVAL / BLOCK) that does complete BFS over provenance before outbound or irreversible actions; Warden agent investigates through MCP tools. Console, docs site at /docs, blog, public-demo mode.
**FalkorDB.** Central: level-by-level read-only traversals (GRAPH.RO_QUERY), `algo.betweenness`, `algo.WCC`, `GRAPH.COPY` sandboxes for what-ifs, three deployment modes (Docker, Cloud, falkordblite). Query catalogue in `docs/cypher-queries.md`.
**Claims.** 330 synthetic cases (290 in scope): Custody precision/recall/F1 1.00 vs TF-IDF RAG best 0.89/0.82/0.85, string match 0.77 F1, keyword scan 0.26. Hypotheses and falsification conditions pre-registered (`bench/HYPOTHESES.md`), committed report. Admits accuracy is "close to guaranteed by construction", SQL recursive CTE matches FalkorDB 330/330 and is faster (0.27 ms vs 22 ms), F3 falsification triggered (1.3 s at 10k ancestors), 10/10 implicit flows missed, 10/10 over-approximation false alarms, no LLM judge run.
**Weaknesses.** Entire demo is scripted and simulated, no LLM is called; says so up front. Security story, not a developer coordination story. Admits SQL does the same job.
**Has, baton lacks.** Pre-registered hypotheses; a self-written failure analysis; GRAPH.COPY what-if; completeness certificates; docs site.
**Verdict.** Best-in-field intellectual honesty, but a different problem. Judges who value negative-result reporting will group it with baton and Relay. It shows the bar for "honest evals" that baton claims.

## 6. thisisvaishnav/guard
**Product.** `guard-cli` on PyPI: after an AI agent edits code, selects the minimal test subset via FalkorDB `COVERED_BY` edges (static call graph plus per-test coverage), computes a Trust Score (0.5 evidence + 0.3 freshness + 0.2 certainty), falls back to run-all on hard overrides (test files touched, no evidence, dynamic dispatch). `guard init` installs Claude Code Stop hook and AGENTS.md. Self-healing `miss_repair` edges.
**Claims.** Flask (494 tests), 24 held-out mutants under a frozen protocol (`evals/split.json`, `PLAN.md`): Guard 0/17 escapes, 67.3% test-time savings, 25% fallback; same-file heuristic and naive-guess 17.6% (3/17) escapes; ablations reported. Mutant diffs committed (`evals/mutants/m01..m30`). Case study of why `m08` escaped baselines. [UNVERIFIED] whether reproduction needs the pinned Flask checkout and a built coverage graph; I did not run it.
**Weaknesses.** Not agent memory or multi-agent coordination, so it is only loosely Track 2 [my judgment]. 17 killable mutants is small; 0/17 has a wide interval (rule of three: upper 95% bound is roughly 17%). Mutants are synthetic.
**Has, baton lacks.** Published PyPI package and installer UX; mutation-testing methodology with frozen split; ablations; strong measurable number (67% savings at 0 escapes).
**Verdict.** Credible, rigorous, but off-track; wins "does something measurable" points. A judge comparing "tokens/time saved" will remember its 67.3%.

## 7. ibold-dev/nexus-mcp
**Product.** TypeScript. ts-morph parses the repo into File/Symbol with IMPORTS and POSSIBLY_CALLS edges (labelled `resolved` vs `heuristic`), plus a memory layer (Session/Turn/Fact/Procedure/Handoff) scoped by userId and repoId. 8 MCP tools (stdio) with config files for OpenCode, Claude Code and Cursor. Reference agent with Anthropic/OpenAI/Google/Ollama providers.
**FalkorDB.** Central to impact analysis (`algo.SPpaths`, backward call walks) and memory attached to symbols via ABOUT.
**Claims.** Bench (`bench/results/2026-10-15T21-19-03-333Z.json`): "Which symbols call normalizeParams?" Nexus 1,164 tokens returned vs 23,568 for a filesystem baseline; "Where is ZodError defined?" 893 vs 60,217; "What did earlier sessions learn?" 228 vs 23,568. 522-file TS repo: cold index about 30 s, 14,162 symbols, 5,184 resolved call edges. 186 tests (README).
**Weaknesses.** Both conditions use a scripted **stub model**, so the "token" figures are bytes returned by tools, not real agent token spend; no outcome measure; the third task compares against a baseline that cannot answer at all. Discloses caps and truncation honestly. Primary track is Track 1. Memory is an add-on to the code graph.
**Has, baton lacks.** TypeScript code graph with type-checker resolution (baton is Python?) [UNVERIFIED for baton language support]; provider-agnostic reference agent; Cursor and OpenCode configs; confidence on each edge.
**Verdict.** Solid engineering, weak on real-agent evidence. Not a direct threat on coordination.

## 8. Aryan7098/codemem
**Product.** Local-first evidence-backed memory: each Memory is SUPPORTED_BY Evidence (file path, AST symbol, content hash, test command and result); git changes flag memories STALE; SUPERSEDES, CONTRADICTS, concept expansion via RELATES_TO*1..2, Handoff nodes referencing memory nodes. CLI, MCP server, in-memory graph fallback. Demo video link is a placeholder ("Upload demo URL here").
**Claims.** `codemem eval`: 10/10 scenarios (100%), categories borrowed from LongMemEval and RepoMem; "Memory Enabled vs Disabled" table: 14 files -> 0, 480 ms -> 8.5 ms (56.5x), 22 -> 1 files, 8 -> 1. 48 unit tests (README).
**Weaknesses.** Eval is self-authored scenarios (10, one or two per category), all pass at 1.00. The latency and "files inspected" comparisons use round figures (480.0, 8.5, 720.0, 12.0) and look scripted rather than measured from agent runs [UNVERIFIED, I did not open `evaluation/runner.py`]. No real agent runs. No dashboard or live site. Staleness-on-change is the one good idea: memory tied to code evidence that expires.
**Has, baton lacks.** Evidence-anchored memory with hash-based staleness; contradiction detection; test-run evidence on claims.
**Verdict.** Weak on proof, decent idea. Judges will see an unreviewed 100% table. Low threat.

## Cross-cutting patterns
- Everyone with a live site, video, and deploy button (Airspace, both Hiveminds, Relay, Kintsugi, Crew) has a visible demo; baton's user records video and deploys at the end, so this gap is known.
- Real-agent A/B with raw runs: only Airspace (n=9/18) and Lecrupus (n=2). Nobody reports token parity or a no-effect result the way baton does, except Lecrupus's in-repo null.
- Statistics: only Relay (CI, McNemar) and Custody (pre-registered). Airspace and baton are in the same position (small n, no significance), but Airspace headlines an effect size large enough that significance is plausible (0/9 vs 9/9 Fisher exact p about 0.00005, my calculation, they do not report it).
- Integrations: Lecrupus (Claude/Cursor/Codex), Quantapixel (Claude/Kiro/Codex), Nexus (OpenCode/Claude/Cursor). Baton is Claude Code only.
- Languages: Airspace, Hivemind x2, Guard are Python-only; Nexus is TypeScript.

## Skeptical-judge ranking (my judgment, not organizer guidance)
1) Airspace (product + real-repo evidence + live), 2) Relay (rigor, polish; domain off-brief for coding agents), 3) Lecrupus hivemind (checklist coverage + candid A/B), 4) Quantapixel hivemind (breadth, no numbers), 5) Baton, 6) Custody, 7) Guard, 8) Nexus/CodeMem.
Baton can move to 2nd-3rd by closing the evidence gap on a real repo and by making the honesty a feature: Baton is the only coding-agent entry that reports cost parity and publishes a null. But today a judge who skims sees "8/10 vs 6/10, p>0.05, warning fired 1 in 40" next to Airspace's "9/9 vs 0/9", and the headline loses. Baton's unique ground: decisions, retraction with blast radius, handoff with last test result, and a hooks-only plugin at cost parity. Nobody else has retraction on code decisions (Relay retires facts, but not for coding).

## 10 things for baton to add or improve (ordered by impact per hour)
1. **Add a "merged build green" metric and a Flask-style real-repo pair benchmark** using baton's existing evals/harbor runner (rename/signature-change pairs with a hidden test per agent, three conditions: none, broadcast, baton). Airspace's whole case rests on this; copy the method, cite the same paper, and publish raw runs. Effort 6-8 h (most infrastructure exists; need tasks and grading of merged tree).
2. **Report exact-test statistics and intervals on every headline** (Fisher exact, Wilson CI) and pre-state the bar, as Relay and Custody do. Rerun to n>=20 per condition on the held-out set. State the 20/21 vs 15/21 (p=0.09) openly alongside effect size. Effort 1-2 h for stats script + 2-4 h runs.
3. **Make the collision warning blocking-once (deny first edit with reason, allow on retry) with a flag**, plus a signature-aware check for Python calls. Airspace and Quantapixel both enforce; "warn only" reads weaker. Check it does not raise token cost; measure. Effort 3-4 h.
4. **A "why baton wins" scenario that nothing else measures: retraction.** Add 10+ real-agent runs where an early decision is retracted and a second session either uses or avoids it, versus a notes-file baseline. Publish regardless of result. Effort 4-5 h.
5. **Lift the code-caller warning firing rate** (fired 1 in 40 trials). Design 10 task pairs where a signature change is guaranteed to make a caller stale (Airspace's idea) and show the warning firing and outcome. Without this the "code graph" feature is unproven. Effort 3-4 h.
6. **Cursor/Codex/Kiro adapter via MCP + a `baton install` command with real captured payload fixtures** (Quantapixel's `tests/fixtures/hooks` approach). Even if only MCP tools (no hooks) are offered, say so in a table with verified/unverified marks. Effort 4-6 h.
7. **Failure-to-fix memory**: link a failing test run to the symbols changed and mark resolved when a later run passes (Quantapixel's Attempt/RESOLVES, Lecrupus's known-fix). Baton already captures last test result at handoff; this extends it. Effort 3-4 h.
8. **Landing check at Stop**: when a session ends, scan its edited files against other sessions' changed signatures and send it back once (Airspace). Reuses the existing code symbol graph. Effort 3 h.
9. **One-command deploy of the dashboard + seeded replay mode** (Airspace "replay", Lecrupus "Play the demo", Quantapixel Vercel): a recorded real run that a judge can open without running anything. The user records video; ask them only to deploy a prebuilt replay. Effort 3-4 h (build replay from an existing run JSON).
10. **Explicit "Honest limits" and token/cost table at top of README** comparing: Airspace +$0.05/pair, Lecrupus +23% cost, baton 1.04x. Plus one cited paper (Passes Alone, Fails Together arXiv:2609.25396 as listed by Airspace [UNVERIFIED by me, ID taken from their README]) and the finding that interference is rare in real PRs, then say what baton measures that bears on that. Effort 1-2 h.

Optional (lower impact): vector recall for decisions (Lecrupus, 4-6 h), TypeScript symbol graph (Nexus/Airspace roadmap, 8+ h), secret redaction before storage (Lecrupus; 1-2 h, cheap and judges like it).
